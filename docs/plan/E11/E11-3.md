# E11-3: Authenticated workspace and agent-creation wizard

## Acceptance criteria
E11-3.AC1 maps F3-S1,F3-S2,F3-S3,F3-S5,F3-S8; test and browser.

## Dependencies
E11-1, E11-2.

## Design
Wizard, landing, sign-in and workspace shell. Implements the real `SessionAuthProvider` (magic link, session cookie, CSRF, logout, `MagicLinkSender` with test capture) behind the E11-1 `AuthProvider` Protocol. Feature: aicl-experience (F3-S1, F3-S2, F3-S3 wizard half, F3-S5 wizard creation, F3-S8).

## Solution approach
Server-rendered landing, sign-in and verification pages, workspace empty state with **Create with wizard** and **Create with chat**, and the wizard form that posts to E11-2 `create_instance` with a per-form idempotency key. Implement the token, rate-limit, no-existence-leak, cookie and CSRF rules from the experience document. The wizard has no budget, connection or credential field.

## Contracts
Own SessionAuthProvider in `docs/design/aicl-experience/technical.md`. Consume CreateInstanceRequest, CreateInstanceResult, AuthContext and AgentInstance. Configuration rows owned: AICL_ENVIRONMENT, AICL_TEST_MODE, AICL_SESSION_SECRET, AICL_SESSION_TTL_SECONDS, AICL_MAGIC_LINK_TTL_SECONDS and AICL_SMTP_* (table in `docs/design/architecture.md`).

## Verification
Integration tests: magic-link TTL, single use, hash-only storage, identical responses for known and unknown emails and rate limits, cookie flags, logout invalidation, CSRF and ignored client tenant, cross-tenant `not_found`, startup rejection of test mode outside the test environment. One browser journey: landing, sign-in with the captured link, wizard creation of a draft instance, field-error denial and a second user not seeing the first user's instance.
