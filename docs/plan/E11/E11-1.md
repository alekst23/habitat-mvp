# E11-1: AICL domain and control foundation

## Acceptance criteria
E11-1.AC1 maps F1-S1,F1-S2,F1-S3,F1-S4,F1-S5,F1-S6,F1-S7,F1-S8,F1-S9,F1-S10,F1-S11,F1-S12,F1-S13; test.

## Dependencies
None.

## Design
Owns the control plane: the application foundation (stack, layout, settings, SQLite migrations and transaction helper per `docs/design/architecture.md`), `AuthContext` with its `AuthProvider` Protocol and `FixedAuthProvider` test double, the instance model and capability grants, the `BudgetPort` and `PriceTable`, the `AuditEvent` log and the `ActionConfirmation` primitives. Features: aicl-control-plane (F1-S1 to F1-S13).

## Solution approach
Create `backend/aicl/{settings,db}.py`, migrations and `backend/aicl/control/` as laid out in `docs/design/architecture.md`. Implement the instance and grant repositories filtered by `tenant_id`, the lifecycle transition table, the gating persistence rule (owner-only clearing, literal D11-8), micro-USD cost math, the single-transaction four-window `reserve`, idempotent `settle`, `mark_unknown`, `reconcile`, `release` and `read_budget`, price-table import with hash immutability and triggers, the append-only `AuditLog` with the redaction allow-list, and the confirmation and pending-action tables. Typed contract stubs and fakes (Protocols, `FixedAuthProvider`, `FakeClock`) are prepared by the Development design worker before tests.

## Contracts
Own AuthContext, AgentInstance (with CapabilityGrant), BudgetPort, PriceTable, AuditEvent and ActionConfirmation in `docs/design/aicl-control-plane/technical.md`. Consumers: E11-2 to E11-5. Shared error taxonomy, conventions and the gate-reason vocabulary are in the same document. Configuration rows owned: AICL_DATABASE_URL, AICL_PRICE_TABLE_PATH, AICL_RECONCILE_INTERVAL_SECONDS, AICL_CONFIRMATION_TTL_SECONDS (table in `docs/design/architecture.md`).

## Verification
Integration tests on real SQLite prove, with as few tests as cover them: tenant isolation and `not_found`; lifecycle table and gating persistence across a window rollover (controllable clock); zero default limits; atomic two-thread reservation across daily and monthly windows; idempotent reserve and settle; over-measured settlement; unknown holds blocking and reconciling; price-table validation, startup failure, use-time `price_unavailable` and trigger immutability; audit append-only triggers and the redaction allow-list; confirmation digest binding, expiry and single use. Unit tests cover cost rounding and the transition table. No browser test (non-UI).
