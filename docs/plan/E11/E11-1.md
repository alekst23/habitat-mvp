# E11-1: AICL domain and control foundation

## Acceptance criteria
E11-1.AC1 maps F1-S1,F1-S2,F1-S3,F1-S4,F1-S5,F1-S6,F1-S7,F1-S8,F1-S9,F1-S10,F1-S11,F1-S12,F1-S13; test.

## Dependencies
None.

## Design
Owns the control plane and the application foundation that every later ticket builds on: stack, layout, the whole `settings.py` validation, SQLite migrations and the unit-of-work transaction helper per `docs/design/architecture.md`; the `create_app` skeleton with its three extension points (`ROUTE_FACTORIES` in `routes.py`, the port registry with the typed `Ports` model and default `build_ports` in `ports.py`, and the ordered `STARTUP_HOOKS` in `hooks.py`); `python -m aicl.test_server` with `npm run start:test`, the test-mode seeded test session, `backend/requirements.txt` and the root `package.json` with `package-lock.json`; `AuthContext` with the `AuthProvider` Protocol and `FixedAuthProvider`; the `CsrfVerifier` Protocol, the shared `require_csrf` dependency and `FixedCsrfVerifier`; the instance model, capability grants and gate-state primitives; `BudgetPort` and `PriceTable`; the `AuditEvent` log (nullable identity for pre-authentication system events); and the `ActionConfirmation` primitives. Features: aicl-control-plane (F1-S1 to F1-S13).

## Solution approach
Create `backend/aicl/{app,routes,ports,settings,db,test_server}.py`, migrations and `backend/aicl/control/` as laid out in `docs/design/architecture.md`, plus `backend/requirements.txt`, `package.json` and `package-lock.json`. Implement: `db.transaction()` and the connection-scoped form `op(conn, ...)` of every mutating repository, `BudgetPort`, confirmation and audit operation (unit of work, so E11-2 composes the gate's step 9 atomically); the instance and grant repositories filtered by `tenant_id` with `set_gated`/`clear_gated` primitives for `gated_reason` and `gate_context` (E11-2 persists `network_denied` only for the owner-resolvable allow-list miss `host_not_allowed`; a structurally invalid destination denies that request and persists nothing); the lifecycle transition table; micro-USD cost math; the single-transaction four-window `reserve(conn, ...)`; idempotent `settle` (on a `released` hold it is `conflict` with a `budget.late_settlement` audit event); `mark_unknown` (from `held`), `reconcile`, `release` (from `held` or `unknown`) and `read_budget`; the rule that only `unknown` and stale `held` holds block while a young `held` hold only counts against the limits; price-table import with hash immutability and triggers; the append-only `AuditLog` with the redaction allow-list and null `tenant_id`/`owner_id` for pre-authentication system events (never returned by owner readers); the confirmation and pending-action tables with `consume_confirmation(conn, ...)`; the `Settings` model validating every row of the configuration table (including `AICL_ENVIRONMENT`, `AICL_TEST_MODE`, both secrets and their placeholder rejection, the fake-only mode rows, the cross-check that `AICL_HOLD_STALE_SECONDS` exceeds `AICL_EXECUTOR_TIMEOUT_SECONDS + AICL_RECONCILE_INTERVAL_SECONDS` and rows whose behavior later tickets deliver); the `create_app` skeleton that runs migrations and the price import, builds `AppContext` through `build_ports(settings)` (the `ports` argument is a test-only override), starts the ordered `STARTUP_HOOKS` and registers an initially empty `ROUTE_FACTORIES` (and empty `STARTUP_HOOKS`); `build_ports` resolves leaf ports from the registry by mode and picks the capture sender only when both test flags are set; the test server as `create_app(test settings)` plus the test-only E11-1 routes (seeded session and clock); E11-3 adds capture routes with its sender, all behind both test flags. Typed contract stubs and fakes (Protocols, `FixedAuthProvider`, `FixedCsrfVerifier`, `FakeClock`) are prepared by the Development design worker before tests. The reconciler and the gating decision (`evaluate_gate_control`, `resolve_gate`) belong to E11-2; E11-1 supplies only the primitives they call.

## Incremental composition delivery

E11-1 starts `create_app` with the base `REQUIRED_PORTS=(clock,)`; it does not require later-ticket ports. It owns Clock and the base registry, while later tickets extend the required-port tuple when they introduce their own ports. Its test routes are seeded-session and clock only.

## Contracts
Own AuthContext, AgentInstance (with CapabilityGrant and `gate_context`), BudgetPort, PriceTable, AuditEvent, ActionConfirmation, CsrfVerifier and AppComposition in `docs/design/aicl-control-plane/technical.md`. Consumers: E11-2 to E11-5 (AuditEvent: E11-2, E11-3, E11-5). Shared error taxonomy, conventions (unit of work, key pattern) and the gate-reason vocabulary are in the same document. Configuration rows owned: AICL_ENVIRONMENT, AICL_TEST_MODE, AICL_DATABASE_URL, AICL_PRICE_TABLE_PATH, AICL_CONFIRMATION_TTL_SECONDS, AICL_HOLD_STALE_SECONDS (passed to `BudgetPort`); E11-1 also implements the startup validation of every other row (table in `docs/design/architecture.md`), whose behavior is owned by the ticket named there. `AICL_RECONCILE_INTERVAL_SECONDS` is owned by E11-2; E11-1 validates its range and the hold-stale cross-check.

## Verification
Integration tests on real SQLite prove, with as few tests as cover them: tenant isolation and `not_found`; lifecycle table and gating persistence across a window rollover (controllable clock); zero default limits; atomic two-thread reservation across daily and monthly windows; the connection-scoped `reserve` and `consume_confirmation` in one transaction rolling back together; idempotent reserve and settle; over-measured settlement; a late settle of a `released` hold as `conflict` with its audit event; `mark_unknown` from `held`, `release` from `unknown`, blocking by `unknown` and stale `held` holds and not by a young `held` hold, and reconciling; price-table validation, startup failure, use-time `price_unavailable` and trigger immutability; audit append-only triggers, the redaction allow-list and events with null identity that no owner reader returns; confirmation digest binding, expiry and single use. Foundation checks: `create_app` starts through `python -m aicl.test_server` with empty `ROUTE_FACTORIES` and `STARTUP_HOOKS`; `build_ports` validates exactly `REQUIRED_PORTS=(clock,)` and does not fail for an unregistered later-ticket port; the development composition has no `/__test__/*` route; a hold-stale value not above the executor timeout plus the reconcile interval fails startup; each invalid configuration row (environment, test-mode combination, short or placeholder secrets, non-fake modes, ranges) fails startup; the seeded session route is absent unless both test flags are set; `FixedAuthProvider` and `FixedCsrfVerifier` behave as specified. Unit tests cover cost rounding and the transition table. E11-1 proves only the primitives of F1-S5, F1-S6 and F1-S9 (the `reserve` denial, the lifecycle table, `set_gated` and `clear_gated`); the end-to-end denial and re-check through the dispatch gate and `resolve_gate` are proved under E11-2.AC1, which also maps those scenarios. All four limits must be positive before any work dispatches (a zero limit is exhausted even for a zero-cost category). No browser test (non-UI).
