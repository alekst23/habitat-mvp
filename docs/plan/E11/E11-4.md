# E11-4: Built-in chat agent creation surface

## Acceptance criteria
E11-4.AC1 maps F3-S3,F3-S5,F3-S6; test and browser.

## Dependencies
E11-2.

## Design
Chat consumes canonical creation only through the first-party tools, with a deterministic engine. Feature: aicl-experience (F3-S3 chat half, F3-S5 chat creation, F3-S6).

## Solution approach
Add the chat state machine (`ScriptedChatModel` behind `ChatModelPort`), `chat_session` and `chat_message` storage, the orchestrator that allows only `list_templates`, `create_instance` and `read_instance`, and `GET /chat` with `POST /chat/messages`. Derive the creation idempotency key `chat_<32 lowercase hex of chat_session_id>_<turn>` (39 to 44 characters of `[A-Za-z0-9_-]`, conforming to the 16 to 64 character key pattern). Treat user and instance text as untrusted escaped data and never touch budget. `read_instance` returns only the E11-2 `InstanceSnapshot`. Register the chat router through the E11-1 extension point and use the E11-1 `require_csrf` dependency. Browser sign-in: the E11-4 journey uses the seeded test session of the E11-1 test server (test mode only, guarded by `AICL_TEST_MODE=1` and `AICL_ENVIRONMENT=test`, not the production sign-in route), so E11-4 needs no dependency on E11-3 and no dependency change. E11-3 proves the real magic-link flow and E11-5 proves production-wired real sign-in.

## Contracts
Own ChatModelPort in `docs/design/aicl-experience/technical.md`. Consume CreateInstanceRequest, CreateInstanceResult, InstanceSnapshot and WebAppToolSchemas, AgentInstance, AuthContext, CsrfVerifier and AppComposition (E11-1) and read-only ConnectionAttachment pointers for links only. Chat holds no reference to confirmation, connection, lifecycle, limit, domain or work operations. Configuration row owned: AICL_CHAT_MODEL_MODE.

## Verification
Unit tests of the state machine and tool allow-list (exact tool list, schema rejection of tenant, credential and confirmation arguments, untrusted text never becoming a tool call, validation-error recovery, retry idempotency, and an assertion that the derived key matches `^[A-Za-z0-9_-]{16,64}$` with length 39 for turn 1 and at most 44 for turn 999999, so no colon can reach `create_instance`); an integration test that the chat `create_instance` tool result equals a direct canonical `create_instance` call (E11-2) for the same `CreateInstanceRequest` and that chat consumes no budget (chat versus wizard equivalence across surfaces is E11-5's, F3-S3); one browser chat journey creating an instance and showing a truthful denial. The browser journey signs in through the E11-1 seeded test session (no password or bypass account in any other composition).
