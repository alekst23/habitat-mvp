# E11-4: Built-in chat agent creation surface

## Acceptance criteria
E11-4.AC1 maps F3-S3,F3-S5,F3-S6; test and browser.

## Dependencies
E11-2.

## Design
Chat consumes canonical creation only through the first-party tools, with a deterministic engine. Feature: aicl-experience (F3-S3 chat half, F3-S5 chat creation, F3-S6).

## Solution approach
Add the chat state machine (`ScriptedChatModel` behind `ChatModelPort`), `chat_session` and `chat_message` storage, the orchestrator that allows only `list_templates`, `create_instance` and `read_instance`, and `GET /chat` with `POST /chat/messages`. Derive the creation idempotency key `chat:<chat_session_id>:<turn>`. Treat user and instance text as untrusted escaped data and never touch budget.

## Contracts
Own ChatModelPort in `docs/design/aicl-experience/technical.md`. Consume CreateInstanceRequest, CreateInstanceResult and WebAppToolSchemas, AgentInstance, AuthContext (E11-1) and read-only ConnectionAttachment pointers for links only. Chat holds no reference to confirmation, connection, lifecycle, limit, domain or work operations. Configuration row owned: AICL_CHAT_MODEL_MODE.

## Verification
Unit tests of the state machine and tool allow-list (exact tool list, schema rejection of tenant, credential and confirmation arguments, untrusted text never becoming a tool call, validation-error recovery, retry idempotency); an integration test that chat and wizard produce the equivalent Default instance through the same service and that chat consumes no budget; one browser chat journey creating an instance and showing a truthful denial. Browser fixtures use the real sign-in.
