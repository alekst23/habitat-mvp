# E11-2: Canonical creation service and web-app tools

## Acceptance criteria
E11-2.AC1 maps F2-S1,F2-S2,F2-S3,F2-S4,F2-S5,F2-S6,F2-S7,F2-S8,F2-S9,F2-S10,F2-S11,F1-S14,F1-S15,F1-S16; test.

## Dependencies
E11-1.

## Design
Owns the canonical creation service and first-party web-app tools (`create_instance`, `InstanceSnapshot`, `InstanceOperations` including `evaluate_gate_control` and `resolve_gate`, tool registry), plus connection and network policy: connections, OAuth, secret store, credential broker, `NetworkPolicy` (pure `check_destination_rules`, `classify_addresses` and resolver-based `authorize_destination`), the `WorkAuthorization` dispatch gate, the work executor port with its deterministic fake, the hold reconciler and the simulated-work and confirmation routes. It registers its routers and real ports through the E11-1 extension point and tests them through the E11-1 `create_app` and test server. Features: aicl-control-plane (F1-S14 to F1-S16) and connection-network-policy (F2-S1 to F2-S11).

## Solution approach
Add `backend/aicl/creation/`, `connections/`, `network/` and `work/`. `create_instance` validates against the one-template catalog and writes the draft instance, grants and audit event in one `db.transaction()` with `(tenant_id, idempotency_key)` idempotency, and returns the lean `InstanceSnapshot`. `InstanceOperations` implements `set_lifecycle`, `set_capability`, `set_limits`, add and remove network domain, `resolve_gate`, `attach_connection` and `detach_connection` with `expected_version`; every mutation that can fix a control, and `resolve_gate` for every reason, call `evaluate_gate_control` and clear the gate only when the control now permits work (otherwise `denied` with `gate_unresolved`; a window rollover never clears). The tool registry exposes only `list_templates`, `create_instance` and `read_instance` (returning `InstanceSnapshot` only) at `POST /app-tools/{name}`. Implement the OAuth begin and callback with state, PKCE and scope checks against `FakeProviderOAuth` (its authorize page registered only in test and development compositions), the AES-256-GCM `SecretStore`, the credential broker and the revocation phases. `WorkAuthorization` runs the fixed ten-step order; step 9 composes `BudgetPort.reserve(conn, ...)` and `consume_confirmation(conn, ...)` in one transaction, and a denial writes `gated_reason` and its audit event in their own transactions. The reconciler (`reconcile_holds`, `AICL_RECONCILE_INTERVAL_SECONDS`) moves a stale `held` hold through `mark_unknown` then `reconcile`, or `release`s it when `WorkExecutorPort.lookup` returns `not_started` (also the result for a `work_id` never seen).

### Internal slice order (no ticket split)
This ticket is broad. Development delivers it in these slices, each merged to the ticket branch with its own tests, all tied to the existing E11-2.AC1 scenarios (one integration test may serve several). Later slices may rely on earlier ones only.
1. Creation, operations and tools (F1-S14, F1-S15, `/app-tools/*`): `create_instance`, `InstanceSnapshot`, `InstanceOperations` with `evaluate_gate_control` and `resolve_gate`, the tool registry. Tests: idempotency, conflict, validation and the key pattern; tool schemas rejecting tenant, owner, credential and confirmation arguments; version conflicts; `resolve_gate` for every reason (denied `gate_unresolved` while the control denies, cleared when it permits, not by a rollover).
2. Connections, OAuth, secret store and broker (F2-S1, F2-S2, F2-S3, F2-S6, F2-S7, F2-S10): attach rules, OAuth state, PKCE, replay, expiry and scope shortfall, revocation including provider failure and the crash sweeper, no credential in any result, audit event or log.
3. Network and SSRF (F2-S4, F2-S5, F2-S8): unit tests of `normalize_owner_domain`, `check_destination_rules`, `classify_addresses` and `authorize_destination` with the fake resolver.
4. Gate, executor, reconciler and routes (F1-S16, F2-S9, F2-S11): gate order and each denial, the atomic step 9 (a failed reservation does not burn the confirmation and the reverse), confirmation single use, expiry and payload mismatch, over-measured and unknown outcomes through the fake executor, stale `held` and unseen `work_id` reconciliation, startup rejection of non-fake modes, HTTP tests of the callback, work-request and confirm routes.
A ticket split is a Planning delta and is used only if Development finds this ticket undeliverable in a bounded loop; none is made now.

## Contracts
Own Connection, ConnectionAttachment, NetworkPolicy, CredentialBroker, ProviderOAuthPort, WorkAuthorization and WorkExecutorPort in `docs/design/connection-network-policy/technical.md`, and CreateInstanceRequest, CreateInstanceResult, InstanceSnapshot, InstanceOperations and WebAppToolSchemas in `docs/design/aicl-control-plane/technical.md`. Consume AuthContext, AgentInstance, BudgetPort, PriceTable, AuditEvent, ActionConfirmation, CsrfVerifier and AppComposition from E11-1. Consumers: E11-3, E11-4, E11-5. Configuration rows owned: AICL_PUBLIC_BASE_URL, AICL_SECRET_ENCRYPTION_KEY, AICL_PROVIDER_MODE, AICL_EXECUTOR_MODE, AICL_EXECUTOR_TIMEOUT_SECONDS, AICL_HOLD_STALE_SECONDS, AICL_RECONCILE_INTERVAL_SECONDS (validated by the E11-1 `settings.py`).

## Verification
Integration tests through the real service and `/app-tools/*` (E11-1 `create_app` and test server) per slice above: creation idempotency, conflict and validation; tool schemas rejecting tenant, owner, credential and confirmation arguments; lifecycle, capability, limit, domain and version-conflict operations; `resolve_gate` re-evaluation for each gate reason; attach rules; OAuth state, PKCE, replay, expiry and scope shortfall; revocation including provider failure and the crash sweeper; gate order and each denial with atomic step 9; confirmation single use, expiry and payload mismatch; over-measured and unknown outcomes through the fake executor; reconciler handling of stale `held` and unseen `work_id`; no credential in any result, audit event or log; startup rejection of non-fake modes. Unit tests cover host normalization, `check_destination_rules` and address classification. No browser test (UI is E11-3 to E11-5).
