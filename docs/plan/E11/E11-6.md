# E11-6: Responsive owner workspace and control UI

GitLab issue: [#19](https://gitlab.com/gitlab-ai-hackathon/transcend-october-2026/43066631/showcase/-/work_items/19)  
Parent: E11 / issue #11  
Branch: `codex/e11-ui-polish`  
State: implementation in progress; not integrated. The workflow status remains
`pending` because this is local Codex work, not a claimed native Duo session.

## Scope

Refine the existing MVP's landing/sign-in, workspace, wizard/chat, agent controls
and Connections UI with a coherent responsive presentation and clear asynchronous
action feedback. This is a separate follow-on to the completed five-ticket
baseline. It does not enable providers, payments, cloud deployment or new agent
capabilities, and it does not merge the epic into main.

## Acceptance criteria

E11-6.AC1 maps F3-S10 and F3-S11 in the [experience spec](../../design/aicl-experience/spec.md).
Verification methods: test and browser. The pages must be usable at desktop and a 375px
viewport, expose shared navigation and truthful owner data, preserve the existing
authentication, creation and control behavior, and show pending/failed/unknown
action feedback while suppressing accidental repeated submissions.

## Dependencies

E11-5, which transitively includes E11-1 through E11-4. All five were integrated
before this ticket began. No new service dependency or provider is introduced.

## Solution approach

1. Reuse the server-rendered template architecture in
   `backend/aicl/web/pages.py` and `backend/aicl/web/manage_pages.py`; add shared,
   repository-owned CSS in `backend/aicl/web/styles.py`. Give public pages a
   simple introduction/sign-in layout and authenticated pages a common brand,
   navigation, page heading and explicit simulated-environment indicator.
2. Present existing owner-scoped projections as agent cards, accurate counts,
   readable control sections, budget tables, connection states and activity.
   Keep the canonical wizard/chat inputs and management forms intact. Preserve
   six-decimal USD values and the distinction between lifecycle and gated state.
   In `backend/aicl/web/routes.py`, normalize only HTML textarea CRLF pairs to LF
   before canonical instructions validation; bare CR remains rejected.
3. Use responsive grid/stacked layouts, contained table scrolling, explicit form
   labels, keyboard focus, safe text wrapping and accessible status feedback.
   Keep all untrusted content escaped and avoid external fonts/scripts/assets.
4. Refine the existing simulated-work, confirmation and OAuth-begin handlers with
   synchronous duplicate suppression, in-flight feedback and truthful errors.
   Unknown work outcomes stay unverified and blocked from resubmission in that
   view; direct the owner to reload and inspect activity rather than retrying.

## Contracts

The canonical contract is [UI refinement (E11-6)](../../design/aicl-experience/technical.md#ui-refinement-e11-6),
including its Presentation contract and Asynchronous action feedback sections.
The existing services/routes produce `WorkspaceView`, `InstanceDetailView`,
`ConnectionsView`, wizard/chat values and structured JSON/error responses; the
updated templates and browser handlers consume them. Reuse the existing CSRF,
expected-version, idempotency, owner-session and confirmation boundaries. No
route signature, form field name, request schema, database transaction, service
port or business rule changes. The wizard's CRLF-to-LF transport conversion
preserves the existing LF/tab instructions contract without permitting bare CR.
New typed stubs are not applicable because these existing
contracts already implement the required behavior.

## Configuration

No new settings, credentials, infrastructure or startup conditions. Existing
fake-provider/test-composition controls and production authentication checks are
unchanged. CSS, fonts and decorative marks require no external network asset.
